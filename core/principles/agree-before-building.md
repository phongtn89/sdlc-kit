# agree-before-building

Most rework comes from building the wrong thing well. Settle intent before code.

- Interview with the `sdlc-grill` skill until every decision that changes architecture, data, tests, security or task split has an answer.
- Ask one question at a time, offer your recommended answer, and stop when the remaining questions would not change the plan.
- Write down the outcome (spec, mini-spec, ADR), not the conversation.
- Use the project's words: read the glossary (`CONTEXT.md` / `GLOSSARY.md` / `docs/glossary.md`) and ADRs first; add new terms when they are agreed.

**Smell:** "I assumed…" in a review comment; a spec with open `[NEEDS CLARIFICATION]` at implement time.
